## 5. Security, auth and authorization rulings
- `signup.approval_required` defaults ON. Signup is two steps, email first; `POST /api/signup` ALWAYS answers the same 202 (never reveals whether an address is registered); same for member invitation (`invited`, names no user); accepting an invitation never asks for or touches an existing account's password.  [Ruled: user 2026-09-15]
- Auth events are rows of the single `audit_log` (`auth.*`), no separate table. Audit records field NAMES only, never values (banking details, private persons).  [Ruled: user 2026-09-09, 2026-09-13]
- Lockout: 5 consecutive failures lock 15 min, carried by the PASSWORD factor (a passkey must still pass while locked); a wrong second factor counts too; refusals for already-locked accounts leave the counter alone; login limiter 10/account+IP/15 min.  [Ruled: user 2026-09-09, 2026-09-16, 2026-09-22]
- MFA: ten single-use recovery codes shown once, hashed (SHA-256); operator reset of MFA is REFUSED (a standing bypass); TOTP secret encrypted under dedicated `APP_MFA_KEY`, never `APP_SECRET`; `company.mfa_required` stays a COLUMN not a setting and is evaluated against the user's memberships, not the working company (switcher cannot bypass); second factor verified BEFORE any session exists; the last factor cannot be removed while the company requires MFA.  [Ruled: user 2026-09-10, 2026-09-22]
- Passkeys: a full second factor (no attestation, user verification required, ES256+RS256); also a FIRST factor (discoverable credentials); a server-checked PIN is REFUSED (10^4-10^6 secret replacing a device-bound one); step-up re-auth (`/api/auth/step-up`) shares the login's five-attempt budget.  [Ruled: user 2026-09-22]
- Forgot password (built `55b4c3f9`): `POST /api/auth/password/forgot` answers 204 for any address (silent for an unknown or disabled account), mails a one-hour link (only the SHA-256 of the token is stored) and the reset ends every session through the security stamp, under the same `NewPasswordPolicy` (12 characters, not breached); limiters 5 an hour per client, 1 per 15 minutes per address, 20 uses per 15 minutes. Connected devices (built `2af701be`): `user_session` keeps the SHA-256 of the session id, the User-Agent, the address and first/last seen (written at most every five minutes); a person ends one or all the OTHER sessions (a revoked row, read by `RevokedSessionListener`), never the asking one; another account's session answers 404.  [ASSUMED: SPEC 2026-10-02 23:36, 2026-10-03 00:16]
- Password policy: minimum 12 + breach list, NO composition rules (NIST 800-63B); the breach check fails OPEN (outage must never block onboarding; the skip is audited); expiry per-company knob defaults to NEVER; history default OFF capped at 5.  [Ruled: user 2026-09-22]
- Non-active (pending/suspended) company answers members and `PermissionVoter` with the SAME 404 as a stranger. Operators hold ONLY platform endpoints; a company's business data answers an operator 404 like a stranger; operators keep NO standing access; support access is owner-granted, time-boxed, read-only by default, visible, audited.  [Ruled: user 2026-09-15, 2026-09-17]
- Role model: owner = `*`; grants follow owner > admin > member; the last owner is never removed or demoted; a role held by a member or an OPEN invitation is refused for deletion, never silently reassigned; custom roles rank below `member` and `RoleBounds::rank()` is fail-closed (0 for unknown). Built 2026-10-03 (`6e715364`, SPEC 08:09/08:31): the built-in `member` is the clerk and holds `invoice.issue` and `payment.write`; creating or issuing a credit note takes the new `invoice.credit` (admin holds it, owner through `*`); the clerk's one refusal answers 404 like a stranger; `SeedPlatform` redefines built-in roles on every run, so existing companies converge.  [Ruled: user 2026-09-15, 2026-09-20; ASSUMED: SPEC 2026-10-03]
- `product.cost.read` is the ONLY way to cost: without it `costPrice` is null (not absent, one generated type), supplier codes are left out, margin is withheld; existing custom roles are NOT auto-granted. "Customer view" hides fields on screen only (API still serves them).  [Ruled: user 2026-09-23]
- `UnauthenticatedSweepTest` walks the ROUTER (not OpenAPI): every `/api` route answers 401 without a session except a listed public set that must equal the firewall's `PUBLIC_ACCESS`; a new public route must be added there deliberately.  [Ruled: user 2026-09-16]
- ONE-WAY DOOR: the fiscal signing key is PER COMPANY, generated at provisioning, encrypted at rest under an env master key; KMS/HSM, German TSE and Portuguese RSA come later as adapters behind the same port; a single platform key and KMS-from-day-one REJECTED.  [Ruled: user 2026-09-20]
- Production refuses to boot (`DevelopmentKeys` in `Kernel::boot()`) on committed dev values of `APP_MFA_KEY`, `REALTIME_TOKEN_KEY`, `REALTIME_API_KEY`; dev ports publish on 127.0.0.1 only (`ComposePortsTest`). Never write live dev passwords into master history; `app:seed --generate-operator-password` prints a one-time password + TOTP secret.  [Ruled: user 2026-09-16, 2026-09-20]
- Portal access is granted, never claimed: no sign-up page; the merchant invites a contact; proposed colleagues stay `en attente d'approbation` until approved; removal never waits.  [Ruled: user 2026-09-20]
- Scanner pairing: single-use link of 256 random bits after `#` (never in logs/Referer), claimed within 5 min, only hashes stored; the phone may only claim, send a scan/choice or take a realtime token for its own channel.  [Ruled: user 2026-09-23]
- Behind a proxy that ends TLS (Caddy), nginx must pass `X-Forwarded-Proto` (private-range trust only) or the API takes every write for cross-site (`csrf_token_invalid`).  [Ruled: user 2026-10-02]
- Seeded dev operator is `operator@twes.local`, dev password passed explicitly by `make seed`/CI; `app:seed` has no built-in password.  [Source: SPEC §7 2026-09-09; password superseded by generated one 2026-09-20, see section 12]

## 6. Fiscal and money rulings (every fiscal rule stays `unvalidated` until an accountant signs)
- Tax-kind set is CLOSED in code (3 kinds with `family`: `vat`/`levy` = percentage_line, `stamp` = fixed_document, `withholding` = withholding_total); only a LEVY may enter the VAT base; regimes exclude families, never codes. TN VAT 19/13/7, FR VAT 20/10/5.5/2.1, FODEC 1 % levy, 1 % retenue a la source.  [Ruled: user 2026-09-13]

## 13. Authorization model (what exists vs what is only researched)
- Permission = dotted lowercase string (`/^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$/`, at least two segments) plus wildcard `*`; `platform.` prefix belongs only to platform operators. `Role::grants()` = EXACT string match or `*`: no prefix matching, no implication. Built-ins `owner => ['*']`, `admin`, `member` live in `SeedPlatform::BUILT_IN_ROLES` (23 and 12 strings at tree 8f0e1c9: counts drift).  [Source: docs/research/authorization.md §0]
- ONE role per person per company (membership unique on user+company). `PermissionVoter` is the single decision point and it judges subscription access (full / read-only / locked) against the permission ASKED, never the role's grants: an owner's `*` passes nothing an unpaid subscription refuses; read-only allows `*.read` + `subscription.read`/`pay`.  [Source: authorization.md §0]
- `Establishment` exists (the fiscal one) but there is NO current-establishment concept: no `CurrentEstablishment`, no establishment filter. Establishment scope on a membership is ruled in principle (2026-09-20), researched, NOT built: a request-scope concept + second filter, join table `membership_establishment` + explicit `all_establishments` flag, owner never scoped; known limit: one role per membership, so a role cannot differ per site. Paired `_own`/`_any` permissions CONFIRMED in principle.  [Ruled: user 2026-09-20; build state Source: authorization.md §4]
- Accounts have password, TOTP, passkeys, recovery codes and NO PIN. `AuditLog` is append-only with ONE actor column. `Me.permissions` is a flat string[] matched exactly or `*` by the client.  [Source: authorization.md §0]
- Till/regulatory finding: the larger requirement than roles is a Register sales JOURNAL (append-only, chained/signed, void = counter-entry, closures with perpetual total); time-boxed delegation reuses the support-access pattern; build NO break-glass. FR does not require operator identification except in training mode (BOFiP §150).  [Source: authorization.md §3, §4.4]
